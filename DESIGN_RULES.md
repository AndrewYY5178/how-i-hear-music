# How I Hear Music — Design Rules

These rules govern every new route and component.

## 1. Read without reading

Every page must pass the blur/squint test. Before copy is read, scale, space, position, density, alignment and graphical form must make the page identity, primary content, primary action and navigation direction clear. Do not solve hierarchy by adding boxes, labels, borders or colour.

## 2. One page, one gravity

Each view has exactly one dominant object. Home foregrounds its editorial headline; track pages foreground the radar; album pages foreground the waveform; Taste foregrounds an idea; Import foregrounds the input. Aim for a 60 / 30 / 10 attention split between primary content, supporting information and utility.

## 3. Rhythm before decoration

Whitespace is structure. Borders only express a real grouping, and cards are never used as the default layout primitive. Establish editorial rhythm with intentional vertical intervals before adding visual detail.

## 4. Type and grid

Use four text levels only: display, section title, body and metadata. Use the 12-column page grid asymmetrically; do not mechanically center every section. A viewport may contain one oversized element, never several competing heroes.

## 5. Interaction and return paths

Visuals must support a task, not decorate it. Any route reached by clicking into a deeper view must provide a visible contextual return action. Pointer interactions always retain button or input alternatives for touch and accessibility.
